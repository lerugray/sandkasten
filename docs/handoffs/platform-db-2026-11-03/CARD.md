Define `PlatformRecord` in `src/types/platformDb.ts` and store committed records in `src/data/platforms/records/<slug>.json` (indexed by `src/data/platforms/index.ts`), covering every platform in `demo.ts`, `demoConfig.ts`, and `lookup.ts` at your base commit (all 14 `MVP_PLATFORMS` IDs: `111` Arleigh Burke Flight II, `598` Ticonderoga Baseline 3, `2740` Nimitz, `1283` Oliver Hazard Perry Long Hull, `342` F/A-18E Super Hornet, `896` F-14D Tomcat, `2471` E-2C Hawkeye 2000, `466` P-3C Orion Update III, `84` SH-60B Seahawk, `2106` Sina/Houdong, `1652` Bayandor PF-103, `1088` Kaman/Combattante II, `265` IRIAF F-4E Phantom II, `264` IRIAF F-14A Tomcat, plus a dedicated Boghammar-class IRGCN fast attack craft record and an Arleigh Burke Flight IIA record ready for the `sim-fix` frigate replacement):
- **Identity & service window:** `slug` (our own id, the record's identity), `legacyIds` (the numeric ids `lookup.ts` uses today, kept ONLY as aliases so the engine keeps resolving them; never mint a new id from CMO's numbering), `name`, `designation`, `className`, `nation`, `service`, `domain` (`"surface" | "sub" | "fixed-wing" | "rotary" | "ground" | "missile"`), `dimension` (`"sea" | "air" | "ground"`), `functionId` (NATO symbol code), `role`, `serviceWindow: { enteredService: number, retired?: number | null, statusNotes?: string }`.
- **Physical & performance figures:** dimensions (`lengthM`, `beamM`/`wingspanM`, `draftM`/`heightM`, `displacementFullTons` or `weightEmptyKg`/`weightMaxKg`, `crew`), `propulsionSummary`, `maxSpeedKts`, `cruiseSpeedKts`, `maxAltitudeFt?`, `combatRadiusNm?`, `enduranceHours?`.
- **Engine-read combat & sensor fields:** `sensorRangeKm`, `weaponRangeKm`, `damagePoints`, `missileDefense` (ships), `weapons[]` (`name`, `type`: `"asm" | "sam" | "gun" | "torpedo" | "aam"`, `rangeKm`, `speedKts`, `pkAir`, `pkSurface`, `quantity`, `warheadDamage`, `seekerType?`, `mountSummary?`, `sourceId`), `defenses[]` (`name`, `type`: `"chaff" | "ecm" | "ciws" | "decoy"`, `effectiveness`, `quantity?`, `sourceId`).
- **Sensors & loadouts:** `sensors[]` (`name`, `type`: `"radar" | "esm" | "ir" | "sonar" | "visual"`, `role`, `band?`, `rangeKm`, `canTrack`, `sourceId`); aircraft `loadouts[]` (`name`, `role`, `combatRadiusNm`, `stores: { weaponName, count }[]`, `sourceId`).
- **Signatures:** `signatures: { radar: { grade, rcsNote }, infrared: { grade, note }, acoustic?: { grade, note }, visual: { grade, note }, sourceId }`.
- **Plain-English briefing:** `brief: { whatItIs: string, howItIsUsed: string, typicalMissions: string[] }` — clear English explaining what the hardware is, how a commander employs it (sensor posture, standoff/escort role, strengths, vulnerabilities), and 3–5 typical missions.
- **Sourcing & provenance:** `sources: { id: string, title: string, publisher: string, year: number, url: string }[]` (US Navy NVR / navy.mil / af.mil fact files, builder spec sheets, CSIS Missile Threat, SIPRI, FAS, Naval Institute / museum archives). Every numeric spec block and weapon/sensor row carries `sourceId` and `provenance: "verified" | "estimated"`. Document estimation formulas for game-engine abstractions (`damagePoints`, `missileDefense`, `pkAir`/`pkSurface`, `effectiveness`, signature grades) in `src/data/platforms/METHODS.md`. Copy nothing from CMO.
- **Engine switch:** `src/lib/platforms/lookup.ts` derives `PlatformInfo` (`getPlatform`, `getAllPlatforms`) from `src/data/platforms/` via `toPlatformInfo(record)` so `detection.ts` and `combat.ts` consume our records with zero edits to `src/lib/simulation/*`. `src/lib/platforms/database.ts` and `src/app/api/platforms/route.ts` serve from `src/data/platforms/` first (`isDatabaseAvailable()` returns `true` from our committed records alone). `data/extraction/` and `data/raw/` remain `.gitignore`d and are never read or bundled.

## 2. Image rule (binding)
- **License gate:** Only Public Domain (`US-Gov` / US Navy / DoD / DVIDS / NARA, or `CC0` / `Public Domain` on Wikimedia Commons) or open attribution licenses (`CC BY` or `CC BY-SA` on Wikimedia Commons; `mil.ru CC BY 4.0`). No unclear-license photos, press/blog scrapes, stock photos, CMO images, or AI-generated art.
- **Stored & shown per image:** Vendor images under `public/platforms/<slug>/` (≤250 KB `.jpg`/`.webp`). Each item in `record.photos[]` stores `localPath`, `caption`, `sourceUrl`, `author`, `license`, `licenseUrl`, and `attributionLine`. The viewer renders `attributionLine`, `license`, and a link to `sourceUrl` directly adjacent to the photo in-game.
- **Clean placeholder fallback:** If a platform has no verified open-license photo after checking Wikimedia Commons and DVIDS, set `photos: []` and `photoPlaceholderReason` (naming what was searched), render a clean terminal technical-silhouette placeholder frame in the viewer, and list the platform in `NOTES.md`.

- **Layout & content:**

  3. **Photo bay:** hardware photo (with multi-photo switcher if `photos.length > 1`) or clean technical placeholder, plus the always-visible credit bar (`author`, `license`, `attributionLine`, `sourceUrl`).

  5. **Complete specs table:** Dimensions & Crew, Propulsion & Performance, Survivability & Signatures, Sensors table, Weapons / Mounts / Loadouts table, and Defenses table, with `[SRC #]` tags on every row.
  6. **Sources block:** numbered bibliography with clickable URLs and `VERIFIED` / `ESTIMATED` provenance tags.
