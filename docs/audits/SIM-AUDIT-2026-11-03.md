# Sandkasten simulation / AI / scenario audit

**Ask:** #ask-dot-s386-1 · **Date:** 2026-11-03 · **Reviewer:** Aide de Camp  
**Pinned candidate:** `lerugray/sandkasten@4f37606d4abcc0f1c8c42b4c34f96946daf3d890`  
**Anchor:** SPEC.md steps 2–6 and GDD.md §§2–6. Ray's goal is to make play easy and streamlined.

The underlying simulation needs fixes independently of the new play view. The two most serious problems are that the player side has no firing path through the audited combat pipeline, and repeated ordinary anti-ship hits cannot damage the demo's large US ships. Running-time commands can also rewind progress.

This is an audit, not an implementation or release gate. No source implementation, scenario date, premise or master branch was changed. **No file under `src/app/play` or `src/components` was read or reviewed.**

## Evidence and limits

Read the requested simulation, AI, scenario, platform and type files, all nine `tests/*.spec.ts` files, and the design anchors at the pin. The tests contain **35 declared tests**; they were inspected, not run. No browser playthrough, screenshot assessment or full battery was performed.

Small deterministic probes exercised the pinned TypeScript functions after Node's built-in type stripping and import-path adaptation. The simulation probe stubbed unrelated AI/event/combat paths where necessary. The stale-hook reproduction used a minimal manually scheduled hook host, **not a mounted React integration test**. Numerical probe results below are distinguished from direct code traces. A production UI symptom is not claimed where excluded caller behavior could change it.

Severity: **S1 breaks core play; S2 produces a wrong result a player notices; S3 is a rough edge.** Reproductions below use scenario/engine fixtures where the existing editor or view's controls were not inspected.

## 1. Defects, ranked

### S1-1. Player units cannot fire through the current combat pipeline

**Receipt:** [src/lib/simulation/combat.ts:292–293](https://github.com/lerugray/sandkasten/blob/4f37606d4abcc0f1c8c42b4c34f96946daf3d890/src/lib/simulation/combat.ts#L292-L293); `src/lib/simulation/gameState.ts:25–31`; `useSimulation.ts:266–281`.

The engagement pass skips every non-AI side. Unit orders contain no target/attack command, and the audited hook/combat API exposes no alternate manual launch path. The demo US Navy side is non-AI. Incoming fire and an armed ship in range therefore cannot produce US return fire through this pipeline.

**Reproduce:** the same eligible shooter/target fixture produced **four launches with isAI=true and zero with isAI=false**. This finding is about the engine contract, not an inspected attack button.

**Smallest fix:** add contact-validated player attack orders and/or the promised self-defense/ROE path. Share targeting validation with AI; do not solve this by giving the player omniscient automatic targeting.

### S1-2. Repeated anti-ship hits never damage the large demo ships

**Receipt:** [src/lib/simulation/combat.ts:216–239](https://github.com/lerugray/sandkasten/blob/4f37606d4abcc0f1c8c42b4c34f96946daf3d890/src/lib/simulation/combat.ts#L216-L239); `src/lib/platforms/lookup.ts:43,58,73,129`.

Each impact compares only its own damage with the platform's original damage points. There is no accumulated damage. C-802 damage 167 divided by Mahan 1190, Bunker Hill 1360 or Nimitz 3600 is below the first 0.15 damage threshold. Any number of penetrating hits leaves an undamaged target undamaged. The carrier-loss objective is consequently unreachable through these ordinary enemy missiles.

**Reproduce:** 20 real C-802 impacts against Mahan with a fixed random value that defeats its defenses and succeeds at the hit roll produced **20 hit events, still undamaged**.

**Smallest fix:** persist remaining health or accumulated damage per unit, subtract every successful hit, and derive damage states from that total. Preserve any deliberate one-hit aircraft rule separately.

### S2-1. Running-time controls can rewind the simulation

**Receipt:** [src/lib/simulation/useSimulation.ts:62–69](https://github.com/lerugray/sandkasten/blob/4f37606d4abcc0f1c8c42b4c34f96946daf3d890/src/lib/simulation/useSimulation.ts#L62-L69), `:140–150,160–235`; `src/lib/simulation/engine.ts:39,59`.

Ticks advance authoritative refs every 50 ms; React state is published every 250 ms. Pause, speed and orders update the older React snapshot, and render writes that snapshot back into the refs. Game, combat and event progress can rewind. The engine also mutates the prior orders Map, so a waypoint can remain consumed while its unit's position rewinds.

**Reproduce:** at 60x, run four 50 ms ticks after a render, then pause. The hook-host probe observed **12,000 ms of simulated elapsed progress since the last rendered snapshot before pause, 0 ms after**; the absolute clock uses Unix time. No double invocation is required.

**Smallest fix:** apply all commands to one authoritative snapshot and publish immutable view snapshots. Never overwrite advancing refs from render; clone mutable Maps and update game/event/combat state together.

### S2-2. Throttle is ignored without waypoints

**Receipt:** [src/lib/simulation/movement.ts:103–115](https://github.com/lerugray/sandkasten/blob/4f37606d4abcc0f1c8c42b4c34f96946daf3d890/src/lib/simulation/movement.ts#L103-L115).

The heading-only branch uses the unit's existing speed and ignores throttle. This also affects units after their final waypoint.

**Reproduce:** clear a 15-knot ship's route, set flank, advance a minute. The probe remains at **15 knots**, not the model's 30-knot flank speed; a stationary unit stays stationary.

**Smallest fix:** resolve commanded speed before both movement branches. Represent an intentional hold/stop explicitly rather than letting stale speed override throttle.

### S2-3. Waypoint arrival teleports short legs and discards travel budget

**Receipt:** [src/lib/simulation/movement.ts:124–145](https://github.com/lerugray/sandkasten/blob/4f37606d4abcc0f1c8c42b4c34f96946daf3d890/src/lib/simulation/movement.ts#L124-L145).

Any waypoint within 0.5 km is reached immediately, regardless of the tick's movement allowance. Arrival ends the tick after one point, discarding remaining travel that could traverse later legs.

**Reproduce:** a 30-knot ship 400 m from a waypoint travels **400 m in a 50 ms tick**, whose budget is only **0.7717 m**. A fast unit crossing several close points instead stops after the first.

**Smallest fix:** consume only reachable distance, carry remaining time across subsequent legs, and use a small numerical tolerance instead of a 500 m snap radius.

### S2-4. Contact uncertainty changes with time-compression selection

**Receipt:** [src/lib/simulation/engine.ts:75–85](https://github.com/lerugray/sandkasten/blob/4f37606d4abcc0f1c8c42b4c34f96946daf3d890/src/lib/simulation/engine.ts#L75-L85).

After 30 stale simulation seconds, uncertainty adds 0.5 km per callback rather than per elapsed simulation time.

**Reproduce:** start with an unknown, 1 km uncertainty contact already 30 seconds old; age it another 30 simulated seconds without detection using 50 ms callbacks (600 at 1x, 10 at 60x). The probe gives **301 km at 1x versus 6 km at 60x**.

**Smallest fix:** derive uncertainty from elapsed simulation age or scale growth by the simulated delta. Equal simulated histories must not produce different information solely because of callback count.

### S2-5. Weak ESM reports preserve falsely precise tracked contacts

**Receipt:** [src/lib/simulation/detection.ts:239–262](https://github.com/lerugray/sandkasten/blob/4f37606d4abcc0f1c8c42b4c34f96946daf3d890/src/lib/simulation/detection.ts#L239-L262).

Every success refreshes the same timestamp, classification never degrades, and uncertainty retains the smallest value ever seen. Yet the new position is jittered using the incoming, possibly much worse uncertainty. ESM can therefore keep a lost precise radar/visual track marked tracked indefinitely.

**Reproduce:** acquire a 0.1 km tracked contact, then supply only 20 km ESM reports. The probe keeps **tracked / 0.1 km** and advances its freshness timestamp while position is randomized using the 20 km report, up to ±0.09° per coordinate. The mismatch is deterministic; the sampled position is not.

**Smallest fix:** separate retained identity from current track quality/freshness. Fuse measurements consistently or use the selected report's positional uncertainty; expire precise tracking when only bearings remain.

### S2-6. Unrelated enemy fire causes incoming-weapon autopause

**Receipt:** [src/lib/simulation/autopause.ts:128–139](https://github.com/lerugray/sandkasten/blob/4f37606d4abcc0f1c8c42b4c34f96946daf3d890/src/lib/simulation/autopause.ts#L128-L139).

The trigger checks launch side, not target or observability. Red firing at a third side pauses Blue as though Blue were under attack.

**Reproduce:** a three-side fixture with no player contacts and a non-player target returns **“Incoming weapon detected” / shouldPause true**.

**Smallest fix:** resolve `targetId` against friendly units and apply the intended threat-observability rule. Group genuinely simultaneous reasons rather than treating every foreign launch as a player emergency.

### S2-7. Low aircraft become surface targets

**Receipt:** [src/lib/simulation/combat.ts:412–421](https://github.com/lerugray/sandkasten/blob/4f37606d4abcc0f1c8c42b4c34f96946daf3d890/src/lib/simulation/combat.ts#L412-L421); `:199–200`.

The air/surface test is altitude above 500 feet. An F/A-18 at 100 feet becomes eligible for C-802/Harpoon and ineligible for air-only missiles.

**Reproduce:** a weapons-free Sina with a low F/A-18 inside range launches **two C-802s** in the pinned probe.

**Smallest fix:** classify by platform dimension. Apply altitude limits separately and share the classification between weapon selection and impact.

### S2-8. Fuel expiry can beat a reachable impact in the same tick

**Receipt:** [src/lib/simulation/combat.ts:133–147](https://github.com/lerugray/sandkasten/blob/4f37606d4abcc0f1c8c42b4c34f96946daf3d890/src/lib/simulation/combat.ts#L133-L147).

The entire tick's travel is subtracted before arrival is checked. A missile that can reach its target before running out of range is nevertheless discarded.

**Reproduce:** target 0.111 km away, remaining range 0.2 km, 530-knot weapon, one-second tick travelling 0.273 km. Probe result: **fuel miss**, no impact.

**Smallest fix:** resolve arrival if target distance is within both this tick's travel and remaining range, then handle exhaustion. Do not merely reverse checks without respecting range.

### S2-9. Doctrine changes leak between missions and disagree across subsystems

**Receipt:** [src/lib/ai/events.ts:276–302](https://github.com/lerugray/sandkasten/blob/4f37606d4abcc0f1c8c42b4c34f96946daf3d890/src/lib/ai/events.ts#L276-L302); `src/lib/ai/aiController.ts:57–73`; `src/lib/simulation/combat.ts:86–97,282–293`.

A mission-only change also writes side overrides. Combat reads side doctrine but ignores static mission doctrine; AI reads static doctrine but not runtime overrides.

**Reproduce:** give one of two Red missions passive radar/weapons-hold through an event. The change appears in Red's side overrides, affecting both missions' fire, while the probe's designated AI unit still returns **radarActive=true**. A static mission hold beneath a free-fire side is likewise ignored by combat.

**Smallest fix:** one effective-doctrine resolver per unit, used by AI and combat, with explicit side/mission/unit precedence and correctly scoped runtime overrides.

### S2-10. Spawned units do not join their declared mission

**Receipt:** [src/lib/ai/events.ts:214–246](https://github.com/lerugray/sandkasten/blob/4f37606d4abcc0f1c8c42b4c34f96946daf3d890/src/lib/ai/events.ts#L214-L246); `src/lib/ai/aiController.ts:65–68`; `demoConfig.ts:166–182`.

Spawn writes a mission label on the unit, but AI looks only in `Mission.assignedUnitIds`.

**Reproduce:** let the demo reinforcement fire. New boats labelled Coastal Patrol keep their initial heading instead of joining the route. The probe gives a spawned member **zero waypoints** while an existing assigned member receives the patrol route.

**Smallest fix:** use a canonical same-side mission ID and an assignment command that updates the authoritative membership.

### S2-11. TriggerEvent marks another event fired without running it

**Receipt:** [src/lib/ai/events.ts:165–174](https://github.com/lerugray/sandkasten/blob/4f37606d4abcc0f1c8c42b4c34f96946daf3d890/src/lib/ai/events.ts#L165-L174); `:103–104`.

The target name is added to firedEvents without executing its actions. A nonrepeatable target is then skipped permanently.

**Reproduce:** A forces B, whose action adds 10 points. The probe returns **zero changes**, with both A and B marked fired.

**Smallest fix:** enqueue forced events for execution, with a cycle guard and one-shot semantics; mark them fired after execution.

### S2-12. A nearby ship can prevent CAP intercepting an aircraft

**Receipt:** [src/lib/ai/aiController.ts:199–203](https://github.com/lerugray/sandkasten/blob/4f37606d4abcc0f1c8c42b4c34f96946daf3d890/src/lib/ai/aiController.ts#L199-L203); `:343–362`.

CAP selects the nearest enemy of any type, then checks that single result for altitude.

**Reproduce:** put a ship 10 km from CAP and an aircraft 20 km away inside its 80 km prosecution radius. CAP does not select the aircraft; removing the nearer ship changes the result.

**Smallest fix:** filter eligible air contacts before selecting nearest, using platform dimension rather than existence of altitude.

### S2-13. A nonrepeating transit restarts after completion

**Receipt:** [src/lib/ai/aiController.ts:289–305](https://github.com/lerugray/sandkasten/blob/4f37606d4abcc0f1c8c42b4c34f96946daf3d890/src/lib/ai/aiController.ts#L289-L305); `src/lib/ai/missions.ts:130–131`.

When its route empties, transit regenerates all reference points. The controller does not consult `repeating`.

**Reproduce:** an A→B transit with repeating=false reaches B, then heads back to A on the next AI update.

**Smallest fix:** persist per-unit mission completion and regenerate only repeating routes.

### S2-14. Neutral ships are treated as hostile automatic targets

**Receipt:** [src/lib/simulation/combat.ts:315–320](https://github.com/lerugray/sandkasten/blob/4f37606d4abcc0f1c8c42b4c34f96946daf3d890/src/lib/simulation/combat.ts#L315-L320); compare `src/types/game.ts:55–57`.

Combat excludes Civilian but not Neutral, although the type helper considers both neutral.

**Reproduce:** place a Neutral ship in range of a weapons-free AI shooter. It is eligible without a hostile-side relationship.

**Smallest fix:** use one explicit hostility/affiliation predicate across detection, AI and combat.

### S2-15. The demo wins on elapsed time, not successful transit

**Receipt:** [src/lib/scenarios/demoConfig.ts:188–213](https://github.com/lerugray/sandkasten/blob/4f37606d4abcc0f1c8c42b4c34f96946daf3d890/src/lib/scenarios/demoConfig.ts#L188-L213); `src/lib/ai/events.ts:100,158–162`; `src/lib/simulation/engine.ts:34,105–133`.

Transit Complete declares victory at 08:00Z with no destination or survival predicate. Event processing also lacks a terminal-result guard. If defeat fired earlier and the engine later continues, the timer can overwrite it with victory. If both events first fire together, the later Carrier Lost event correctly wins that particular ordering; do not misdiagnose that case.

**Reproduce:** the pinned demoConfig probe advances to T+2h with all units unmoved: it returns **victory**, carrier still at longitude 57.5, latitude 25.2. The result-overwrite claim concerns continued engine evaluation, not an inspected modal or resume control.

**Smallest fix:** define destination/survival predicates, explicit failure precedence and a persistent terminal state. Keep Ray's chosen date/premise.

### S2-16. Expendable defenses never run out

**Receipt:** [src/lib/simulation/combat.ts:183–194](https://github.com/lerugray/sandkasten/blob/4f37606d4abcc0f1c8c42b4c34f96946daf3d890/src/lib/simulation/combat.ts#L183-L194).

Defense quantity is checked but never decremented or stored. A 24-use chaff supply can defend impact 25 and beyond. Every defense also rolls against every threat, without checking seeker/type, including acoustic decoys against missiles.

**Reproduce:** a deterministic Mahan fixture defended **30 consecutive injected impacts**, while its 24-use chaff quantity remained **24**. The cross-threat applicability issue is a separate direct source trace, not this depletion probe.

**Smallest fix:** track defense expenditure per unit, not in shared platform templates, and filter applicable countermeasures by threat/seeker.

### S2-17. Event side filters can fire the wrong narrative or result

**Receipt:** [src/lib/ai/events.ts:335–338](https://github.com/lerugray/sandkasten/blob/4f37606d4abcc0f1c8c42b4c34f96946daf3d890/src/lib/ai/events.ts#L335-L338), `:442–444`.

UnitDetected ignores the requested target side; SideIs returns true unconditionally.

**Reproduce:** two independent probes: (1) request Blue detecting Iran but supply only a Blue-owned Red contact; one score action fires. (2) destroy a Red unit while requiring SideIs Blue; one score action still fires.

**Smallest fix:** carry triggering-unit context into conditions, join contacts to actual unit sides, and evaluate both detecting and detected sides. Do not silently accept unsupported conditions.

### S2-18. AI uses true enemy positions without detection, while its detection event cannot fire

**Receipt:** [src/lib/simulation/combat.ts:279,315–333](https://github.com/lerugray/sandkasten/blob/4f37606d4abcc0f1c8c42b4c34f96946daf3d890/src/lib/simulation/combat.ts#L279-L333); `src/lib/ai/aiController.ts:172–176,199–203,330–362`; `src/lib/simulation/engine.ts:136–139,172`; `demoConfig.ts:128`.

AI pursuit and firing select actual opposing units rather than the side's contacts. Meanwhile the normal detection path creates contacts only for the player side. Thus AI sees perfect target positions for action, but the demo's Iranian Escalation event waits for an Iran-owned contact that this path never creates. Iran already starts weapons-free, so the missing event does not currently prevent shooting.

**Reproduce:** Sina and Mahan about 80 km apart, contacts empty, both radars off, Iran passive/weapons-free: the actual combat probe launches **four C-802s**. The actual escalation event with the engine's US Navy-owned contact returns **zero fired events**. This does not assert a real-world sensor-range limit; it proves detection is not required by the code.

**Smallest fix:** maintain side-owned contact stores for every side, use each side's valid contacts for targeting, and feed those detections to events. Fix together: adding a contact gate alone would silence AI because it currently has no normal contacts. GDD §§4.1 and 6.1 describe detection and contact-based engagements.

### S2-19. Time compression reduces detection opportunities

**Receipt:** [src/lib/simulation/engine.ts:17,67–69](https://github.com/lerugray/sandkasten/blob/4f37606d4abcc0f1c8c42b4c34f96946daf3d890/src/lib/simulation/engine.ts#L17-L69).

The five-second detection gate runs once when due and resets its timestamp to the current time, discarding excess elapsed time. At 60x, each ordinary 50 ms callback advances three simulation seconds, so subsequent five-second gates occur every six seconds.

**Reproduce:** fresh engine, Unix-dated scenario, one friendly/one enemy, no autopause, exactly 60 simulated seconds in 50 ms callbacks: the cadence probe counts **12 scans at 1x versus 10 at 60x**. This changes detection opportunities independently of the uncertainty-aging defect.

**Smallest fix:** retain the scheduled cadence remainder. For longer delayed callbacks, process scheduled substeps with the appropriate intervening state rather than silently dropping sensor windows.

### S3-1. Clarify whether the reinforcement chance is once or recurring

**Receipt:** [src/lib/scenarios/demoConfig.ts:146–153](https://github.com/lerugray/sandkasten/blob/4f37606d4abcc0f1c8c42b4c34f96946daf3d890/src/lib/scenarios/demoConfig.ts#L146-L153); `src/lib/ai/events.ts:104–119,323–324,410–411`.

The Time trigger stays true after T+45m. A failed RandomChance condition is retried each tick. The code proves repeated trials, but nonrepeatable can mean once *successfully fired*, not necessarily one chance roll. A designer-intent decision is needed before treating this as a wrong-result S2.

**Reproduce:** a fixed 0.8 random result fails, then 0.1 on the next tick spawns the reinforcement. Ten independent 0.6 trials imply **99.9895% cumulative probability**. This only contradicts the design if a single 60% branch was intended.

**Smallest fix:** document the chosen semantics. If this is a one-shot 60% branch, record/pre-roll the opportunity once; otherwise describe an eventual recurring opportunity. Test the chosen behavior without globally changing recurring conditions.

### S3-2. Database readiness does not mean its dependent data exists

**Receipt:** [src/lib/platforms/database.ts:26–30](https://github.com/lerugray/sandkasten/blob/4f37606d4abcc0f1c8c42b4c34f96946daf3d890/src/lib/platforms/database.ts#L26-L30), `:41–86,141–142`.

Readiness checks only ships.json. Other missing files silently become empty Maps.

**Reproduce:** provide ships.json but omit weapons/sensors/loadouts: availability is true while their getters are empty.

**Smallest fix:** validate the complete required dataset and return per-file readiness/errors. The bundled sim uses lookup.ts separately; this finding does not claim the current view exposes an empty database screen. SPEC's own-source database migration must not be “fixed” by shipping extracted CMO data.

## 2. Streamline the retained systems

These are proposals grounded in tests/APIs, not a review of the replacement view:

- **Batch placement:** sand-001:47–51 reselects the same platform before each placement. Keep placement sticky until Done/Escape.
- **One command path:** route pause, speed, sensor, throttle and mission changes through the authoritative engine command queue; acknowledge the applied state rather than silently reverting it.
- **One mission identity:** replace the split display label/membership list with validated assignment and show effective mission/doctrine plus a reason when an order is unavailable.
- **Explain victory:** present the destination, protected units and live progress from the actual win predicate, not a timer masquerading as transit success.
- **Plan a complete route:** accept a route transaction, validate its legs, and expose speed/ETA and a clear hold/cancel state.
- **Pause once per event batch:** collect simultaneous actionable reasons and let Continue acknowledge that batch; preserve newly arriving danger.
- **One platform record:** bind identity, dated fit, sensors and combat loadout to the same sourced record, with explicit approximation/unavailable-data labels.
- **Checkpoint deliberately:** add a versioned snapshot/restore contract and concise restored-state summary if live-game saving is intended. No checkpoint API exists in the audited hook, but an excluded UI save workflow was not inspected and is not declared broken.

## 4. Test gaps and the smallest useful regression plan

The existing Playwright suite is useful smoke coverage, not proof the rules work:

| Existing test | What is missing |
|---|---|
| `sand-001:47–66,79–95` | Three placements are asserted; the drag deliberately has no changed-position assertion. |
| `sand-002:17–32` | Any row eventually reaching TRK passes; stable identity, intermediate stages, decay and reacquisition are untested. |
| `sand-003:34–75` | Track shapes and any combat outcome pass; no target validity, ammo depletion, cumulative damage or player-return-fire assertion. |
| `sand-004:23–44` | Tests first contact then disables it; no pause-frequency bound, unrelated-side threat filter or complete simultaneous-reason handling. |
| `sand-005:13–40` | God mode reveals units; toggling fog back on and lost-track concealment are untested. |
| `sand-006:38–103` | Route entry, speed/heading change and manual clear are tested; actual arrival, conserved distance, no-route throttle and transit completion are not. Computed featureCount is not asserted. |
| `simulation.spec.ts:7–21,39–52,106–115` | Automatic resume can hide pause storms; clock only has to differ; reset only has to show 06:00:00. |
| Smoke/design tests | Mostly presence/navigation/screenshots. Screenshot creation is not a simulation assertion or a completed visual review. |

Add deterministic engine tests and a small real React/fake-timer harness before expanding flaky end-to-end waits:

1. **State/time:** commands at every 50/250 ms boundary; no rollback of clock, position, ammo, damage, events or orders; reset/remount and two independent simulations.
2. **Cadence/movement:** identical simulated duration at 1x/10x/30x/60x and a late callback; short/multiple/final waypoints, no-route throttle and explicit speed/altitude semantics.
3. **Sensors:** equal-time scan counts across compression levels; side-owned contacts driving AI and events; the same contact through fusion, classification, sensor loss, uncertainty growth, downgrade, expiry and reacquisition; fog toggled both ways.
4. **Combat:** player and AI engagement, ROE/neutrality, low aircraft, cumulative damage, exact ammo/defense depletion, terminal fuel boundary and target removal.
5. **Missions/events:** spawned assignment, one-time transit completion, eligible CAP selection, doctrine precedence, forced events, side filters, one-shot random branches and exclusive persistent endings.
6. **Demo:** waiting outside the destination cannot win; carrier loss cannot later become victory.
7. **Autopause:** one pause per acknowledged event batch, no unrelated target alerts, new danger still interrupts, preference/reset semantics.
8. **Catalog/persistence:** validate IDs, mission references and dated profiles. A live-save contract must round-trip Maps/Sets plus game/combat/event/scheduler state; JSON-stringifying GameState alone is insufficient.

### Explicit non-findings

Target-gone weapons are removed (`combat.ts:124–127`), so no “missiles live forever after target removal” defect is asserted. Basic overshoot has an arrival comparison; the proven missile bug is fuel-check ordering. No production double-interval subscription or inevitable stuck-waypoint loop was established; cleanup exists. Module-global clocks and absent checkpoint APIs warrant tests, but excluded mount/save callers were not inspected, so no speculative navigation or save-loss defect is promoted.

**Suggested fix order:** authoritative state and cumulative damage/player combat first; then movement/sensors and doctrine/mission/event correctness; then validated scenario/catalog facts and the streamlined command feedback. The new rendering work can consume these corrected contracts without reopening its files in this audit.
